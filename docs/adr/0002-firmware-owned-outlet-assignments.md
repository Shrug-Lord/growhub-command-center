# Firmware-owned outlet state

CE firmware owns outlet assignments and outlet labels, and Command Center mirrors that state before editing or loading schedule templates. Command Center may request full outlet-state replacements, but accepted firmware state is authoritative and schedule templates must be preflighted against it. Command Center therefore treats outlet assignment and label editing as a first-class device setup workflow. Schedule editing may use the last mirrored outlet state, but schedule loading requires MQTT connectivity and current retained outlet state for the target device before compiling or publishing a firmware schedule. This avoids duplicated configuration and lets local firmware UI changes remain visible to Command Center, at the cost of blocking schedule loads when Command Center cannot confirm current firmware outlet state.

Command Center allows outlet label changes at any time because labels do not drive firmware schedule validation. Outlet assignment changes can affect active automation, so when a device is in AUTO or already has an active schedule, Command Center requires explicit confirmation before sending a replacement outlet configuration. After an accepted assignment write, Command Center refreshes both outlet state and schedule state because CE firmware may clear affected schedule entries and re-evaluate affected outlets.

When label drift is detected during schedule preflight, Command Center may offer an explicit outlet label repair action, such as renaming the device outlet to the template's expected label. Label repair is sent as a firmware-owned outlet configuration write, which means Command Center sends a full replacement outlet config for all physical outlets and waits for retained `outlets/state` before rerunning preflight. Schedule loading never silently renames firmware-owned outlet labels.

Outlet label repair is treated as a pending outlet config action and is serialized per device with other outlet configuration writes and schedule loads. Command Center blocks outlet label repair while a schedule load or another outlet config action is pending, and blocks schedule loads while outlet label repair is pending. Even label-only writes are serialized because schedule preflight depends on clean retained `outlets/state` confirmation before compiling and loading.

Command Center confirms outlet label repair and other outlet config writes from a newer retained `outlets/state`, not MQTT publish success. Because CE firmware accepts `outlets/config` as a full replacement, Command Center stores the intended full outlet config for the pending action and confirms only when the newer retained outlet state matches the intended physical outlet IDs, assignments, and labels. A relevant post-handoff `outlets/error` rejects the action; if neither matching newer outlet state nor an error arrives within the uniform 15-second deadline measured from MQTT handoff, Command Center marks the action timed out and does not retry automatically. Later matching state updates the firmware-owned mirror but does not rewrite terminal action history.
