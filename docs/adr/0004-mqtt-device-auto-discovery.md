# MQTT device auto-discovery

Command Center auto-discovers Growhub devices from valid retained CE firmware MQTT topics and keeps a local device registry keyed by MAC. The server subscribes to firmware presence, sensor, outlet-state, and schedule-state topics, but only a validated retained presence, outlet-state, or schedule-state message may create a new device registry entry. Sensor messages and error topics may update or diagnose an already known device but do not independently register one. Retained `status` drives device presence, while retained outlet and schedule state let Command Center show useful device state before the next sensor packet arrives.

Manual device registration is not required for local-first shipping. This keeps setup simple and matches the CE firmware topic model, at the cost of letting stale or unintended broker-visible devices appear in the local registry. First ship provides a Command Center-owned display-name override and a durable hide control for stale or bench devices without changing firmware identity. It does not present deletion as durable removal: a device can be rediscovered while valid retained CE topics for its MAC remain on the broker, so hiding is the stable local suppression behavior.
